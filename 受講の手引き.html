AI駆動開発（AIDD）研修 ／ 受講者向け

AIDD通し演習 受講の手引き

1つのアプリを、要件定義から引き渡しまで7章で作り切る実践演習です。各章にAIの相手役がいて、あなたの判断を受け止め、問い返し、採点します。この手引きは、始める前に全体像をつかむためのものです。

この演習のゴール
品質を上流で作り込み、それを顧客と約束できる状態になること。

欠陥の多くは、実装ではなく要件と合意の段階で生まれます。AIに実装させる時代ほど、何を決めて誰と合意したかが品質を決めます。最後に持ち帰るのはアプリではなく、次にAIへ実装を頼むときの指示書です。

題材 社内 備品貸出アプリ（新規開発） 技術 Next.js ＋ TypeScript ＋ Prisma ＋ SQLite（固定） 所要 8.5〜14時間（2日・目安）
育てるもの

この研修で身につけてほしい2つの力

上流で品質を作り込む力

曖昧な要望を逆質問で要件に落とし、設計・テスト計画・実装・検査へと、決めたことを落とさずに運ぶ力。欠陥がどこで生まれたかを分類し、次の指示に変える力。

主に鍛える章：Ch.1・Ch.1.5・Ch.2・Ch.3・Ch.6

顧客と約束する力（プリセールスの土台）

顧客から本当の困りごとを聞き出す。選択肢をトレードオフつきで示す。決裁者に判断材料を渡して合意を取る。非エンジニアに画面と言葉で説明する。

主に鍛える章：Ch.1・Ch.1.5・Ch.6
提案書の作り込みや競合比較などは、別コース「プリセールス応用編」で扱います。
全体の流れ

7つの章と相手役

前の章で整えた成果物が、そのまま次の章の入力になります。章の重みは均等ではありません。Ch.1（逆質問）とCh.4（コードの検査）に時間を使ってください。

Ch.1要件定義

曖昧な要望を、逆質問で要件に落とす重点

総務の佐藤さんから「簡単なやつでいいので、いい感じに」と相談が来ます。佐藤さんは聞かれたことにしか答えません。手法（INVEST・MoSCoW・EARS・受入条件）をAIに回させて仕様に整え、画面イメージ（モック）を作って佐藤さんに見せます。

相手役 顧客（総務・佐藤さん）目安 90〜150分成果物 受入条件つき要件＋画面イメージ
Ch.1.5提案・合意

要件を、決裁者が判断できる形にして合意を取る新設

佐藤さんの上長である部長に、A4 1枚の提案書と概算見積を持っていきます。部長は画面の細部ではなく、効果・費用・時期・リスクで判断します。質問や反論を受けて案を直してください。

相手役 決裁者（総務部長）目安 60〜90分成果物 提案書1枚＋概算見積＋合意した計画
Ch.2設計・構造化

要件を、実装できる情報に構造化する

8つのセクション（目的・前提条件・影響範囲・受入条件・技術設計・確認事項・備考・関連ファイル）に整理します。これは現場でいう親チケットの本文です。書き写すだけでは通りません。実装者が迷わない粒度まで足してください。

相手役 設計レビュアー目安 60〜90分成果物 8セクションの設計（親チケット）
Ch.3計画・テスト

どこを厚くテストするかを決め、AIに渡す子チケットに分ける

品質リスクマップ、4層（UT・IT・ST・E2E）のテスト戦略、完了基準（DoD）を作ります。全部「高リスク」にするのは、優先順位をつけていないのと同じです。最後に、親チケットを、AIが1回で正しく実装できる子チケット（3〜8枚）に分け、着手してよいか（DoR）を確かめます。

相手役 QAリード目安 75〜105分成果物 テスト戦略・完了基準・子チケット
Ch.4実装・検証

AIに実装させ、そのコードを自分で検証する重点

子チケットを実装役のAIに渡すと、実際に動くアプリを作って、子チケットごとに「できました、問題ありません」と報告してきます。その報告を鵜呑みにせず、4つの観点で検査してください。動いている＝正しい、ではありません。

相手役 実装役AI／レビュー役目安 90〜120分成果物 動くアプリ＋検査結果
Ch.5セキュリティ

ガイドラインに照らして点検し、直す順番を決める

Ch.4のコードを9項目で点検し、Phase 1〜3の修正計画を立てます。「問題なし」が正解の項目も混ざっています。全部を問題扱いにすると、それも指摘されます。

相手役 セキュリティ監査役目安 60〜90分成果物 判定＋修正計画
Ch.6引き渡し・振り返り

直して、顧客に見せて、なぜそうなったかを振り返る

Phase 1を実際に直し、直ったことを自分で確かめます。佐藤さんに完成品を見せ、反応を受け止めます。最後に、欠陥の由来を3つに分類し、次回の指示書に変えます。

相手役 顧客（佐藤さん）／評価者目安 60〜90分成果物 次回の指示書

所要時間は机上の目安です。章ごとに区切り、間を置いて進めることを勧めます。前の章で自分が何を決めたかを覚えていないと、次の章で検出できないものがあるためです。

章のつなぎ方

引き継ぎブロックを貼って、次の章へ

各章で「評価して」と頼むと、採点のあとに ━━━ 次章への引き継ぎ ━━━ というブロックが出ます。これが次の章の入力です。コピーして保管し、次の章の最初に貼ってください。Ch.1とCh.1.5のブロックは、2つの章で使います。

章出題のときに貼るもの
Ch.1なし（題材を伝えるだけ）
Ch.1.5Ch.1 の引き継ぎ
Ch.2Ch.1 の引き継ぎ ＋ Ch.1.5 の引き継ぎ
Ch.3Ch.2 の引き継ぎ
Ch.4Ch.3 の引き継ぎ（実装を頼むときは、その中の子チケットを貼る）
Ch.5Ch.4 の引き継ぎ
Ch.6Ch.5 の引き継ぎ ＋ Ch.1.5 の引き継ぎ

掘り切れなかった論点は、引き継ぎに「未決定」と書かれます。勝手に埋められることはありません。未決定のまま進んでも構いませんが、次の章で必ず聞かれます。

採点の見方

観点ごとに、3段階で判定されます

各章の評価役は、観点ごとに次の3つで判定します。判定は印象ではなく「何がいくつ書けているか」で決まるよう作ってあり、誰が受けても同じ提出物には同じ判定が出ます。

達成

必要な要素がそろっていて、次の工程の人が追加の質問なしで動ける。

一部

要素はあるが、一部が欠けている。具体の値が無い、片方の系だけ、など。

未達

その観点に当たる記述が無い、または内容が誤っている。

「レビューして」と頼むと、採点せずに甘いところだけを指摘してもらえます。何度でも受けられます。整ったら「評価して」と頼んでください。

約束ごと

演習を成り立たせるための6つの約束

  • 手法はAIに回させ、判断はあなたがするINVEST や MoSCoW は暗記しなくて構いません。投げ方は同梱の『手法をAIで回すプロンプト集』にあります。AIの出力のうち、何を捨てて何を直したかを「判断の記録」に書いてください。そこがあなたの仕事です。
  • 相手役は、聞かれたことにしか答えない顧客も部長も、大事な事情を自分からは話しません。要望を言うだけでは粘られます。目的と因果でつないだ説明をすると、相手は動きます。
  • 判断を丸投げしない「考えておいて」と頼むと、AIは選択肢と推奨を示し、「どれにしますか」と返してきます。選ぶところまでが、この演習で身につけてほしい仕事です。
  • 答えのファイルを開かない.claude/agents/・internal/・logs/・模範解答_Ch1.md には答えが書いてあります。先に見ると練習になりません。AIにも読ませないでください（模範解答_Ch1.md は、Ch.1 の採点を受けたあとなら開いて構いません）。
  • Ch.4のコードは、Ch.5が終わるまで直さないCh.5はそのコードを点検する章です。直すと点検対象が消えます。修正はCh.6で行います。
  • 相手役への発言は、相手役に届ける取り次ぎのAIが勝手に顧客を演じたり、先回りして「次はこれを聞くと良いですよ」と言い始めたら、止めてください。「spec-sparring-client に聞いて：…」のように相手役の名前を明示すると確実です。
最後に持ち帰るもの

「気をつける」で終わらない指示書

Ch.6で、見つかった欠陥を由来で3つに分けます。(a) 要件で決めなかったから起きた／(b) 設計に書いたのに実装で落ちた／(c) 誰も指示していないのにAIが足した。その分布から、次にAIへ実装を頼むときの指示書を作ります。分かれ目は、読んだ人が同じ判断をできるかどうかです。

残らない書き方
  • 権限チェックに気をつける
  • 要件にない機能を作らないよう注意する
次から効く書き方
  • 実装依頼の定型文に「APIルート全ファイルについて、所有者チェックの有無を一覧にして報告すること」を入れる
  • レビュー時に、要件のスコープ表に無いファイルが増えていないかをファイル一覧の差分で確認する

指示書は、置き場所も分けて書きます。毎回読ませる絶対ルールは CLAUDE.md、特定の領域だけの注意は .claude/rules/、使い回す手順は .claude/skills/、実装依頼の定型文や完了報告の書式はチケットテンプレート（Backlog・Jira・GitHub Issues などの課題テンプレート）、経緯はプロジェクトメモリへ。全部を CLAUDE.md に入れると肥大化し、AIがどれが重要か判別できなくなります。

はじめかた

演習フォルダでClaude Codeを起動する

  1. 演習フォルダに移動して、Claude Code を起動します。必ずこのフォルダで起動してください。別の場所だと相手役のAIが見つかりません。

    cd ~/Desktop/aidd-curriculum && claude

  2. 動作を確認します。佐藤さんから曖昧な相談が返ってくれば準備完了です。

    spec-sparring-client で出題して。題材は equipment-lending。

  3. 手法をAIで回す作業用に、演習フォルダの外でもう1つ claude を開いておくと便利です。相手役とのやり取りと、手元の作業を分けられます。

演習のルール（答えを読まない・先回りしない・相手役はサブエージェントに任せる）は、同梱の CLAUDE.md に書いてあり、自動で読み込まれます。毎回チャットで伝える必要はありません。詳しい手順と各章の提出フォーマットは 受講者ガイド.md にあります。
