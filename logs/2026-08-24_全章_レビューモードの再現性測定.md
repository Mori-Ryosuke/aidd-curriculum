# 全章：レビューモードの再現性 測定記録

- 実施日：2026-08-24
- 対象：Ch.1〜Ch.6 の各エージェントの**レビューモード**（採点ではなく指摘だけを返すモード）
- 前提：`.claude/agents/**` の deny を一時解除して編集し、作業後に必ず復元している

---

## 1. なぜこの測定をしたか

これまでの測定はすべて**評価モード**（採点）だった。だが受講者は、評価に出す前に
レビューモードを何度も使う。ここが揺れると、**同じ提出物でも人によって受け取るヒントの量が変わる**。

採点結果が揃っていても、そこに至る道筋が揃っていなければ演習の難易度は人ごとに変わる。

## 2. 何を見たか

レビューは自然文なので**文言の一致は求めない**。見たのは3点。

1. **モードを守るか** — 採点表・充足数・引き継ぎブロックを出さないか
2. **指摘の集合** — どの論点を拾ったか（言い回しではなく論点の同一性）
3. **答えを言わないか** — 隠し論点の名指し、欠陥の件数、正解の判定を漏らさないか

使った提出物は、各章の**薄い提出物**（薄い提出物での測定で使ったものと同一）。

## 3. 結果（第1ラウンド）

| 章 | モード遵守 | 指摘の集合 |
|---|---|---|
| Ch.1 | **違反**（評価モードへ昇格） | 割れ |
| Ch.2 | 遵守 | 1件差（Excel移行） |
| Ch.3 | 遵守 | **一致** |
| Ch.4 | 遵守 | 割れ（欠陥件数の開示） |
| Ch.5 | 遵守 | **一致** |
| Ch.6 | 遵守 | 割れ（表の6行目） |

### ★Ch.1 のモード違反が最も重い

「レビューしてください」に対し、1体は
**「レビューとのことでしたが、提出物として採点します」と宣言して評価モードに昇格**し、
11観点のスコア表・充足数・Ch.2への引き継ぎブロック・**隠し論点3つの名指し**まで出力した。
もう1体はレビューのみを返した。

**受講者が一言お願いしただけで、運が悪いと答えが全部出てくる状態だった。**
掘り当てが演習の中心なので、これが起きると章が成立しない。

原因は Ch.1 のモード判定の矛盾：

- 冒頭の動作モードは4つ（出題／顧客応答／モック確認／評価）で、**レビューが列挙されていなかった**
- 判定に「**評価や提出仕様があれば評価**」と「**レビューだけならレビュー**」が同時に存在
- さらに「どちらとも取れる場合は評価モードを選ぶ」が昇格側に押していた

以前「出来が悪いことを理由に評価→レビューへ**降格**するな」と強化した対策が、
今度は**昇格**を招いていた。両方向を塞ぐ必要があった。

## 4. 加えた修正

| 章 | 修正 | 結果 |
|---|---|---|
| Ch.1 | 動作モードを5つにしてレビューを列挙／判定を順序付きにし「最初に当たったもので確定・後ろで上書きしない」／昇格の禁止を降格の禁止と対に明記／レビューでは隠し論点を名指ししない | モード違反は解消。**中身は未収束** |
| Ch.4 | レビューモードの出力仕様（順序・出してよいもの・出してはいけないもの）を追加。残数の開示を必須化 | 1回目は失敗、2回目で**収束** |
| Ch.5 | 同上の出力仕様を予防的に追加 | **一致**（元から揃っていた） |
| Ch.6 | 上限7件を撤廃／表6行目の該当条件に「一切言及が無い場合」を追加／飛ばした行の申告を追加 | 3回目で**収束** |

## 5. 分かったこと

### (1) ★条件文の精密化は、この日だけで4回失敗した

Ch.1 INVEST、Ch.2 AIペルソナ活用、Ch.4 残数、Ch.6 表——いずれも
「条件をより正確に書く」方向の修正が効かなかった。効いたのは別の軸だった。

### (2) 効いた対策は3つの型に分かれる

| 型 | 例 | 効いた理由 |
|---|---|---|
| **書く文字列を1つ指定する** | Ch.4 の `**5個中 M個 検出。残り N個。**` | 禁止は網羅できないが、指定は1つで済む |
| **飛ばし・内訳を申告させる** | Ch.6 の「飛ばした行：なし」／Ch.3 の内訳と合計 | 落としたことが出力に残るので、数える動作が強制される |
| **見る場所を1か所に固定する** | Ch.2 の `■ 自己点検の記録` 欄 | 判定材料が散っている観点は、条件をどう書いても揺れる |

### (3) ★禁止の列挙は抜け道を作る（この日、自分で再現してしまった）

Ch.4 の1回目の修正で「『複数残っています』『まだあります』のような**ぼかした言い方をしない**」と
禁止例を並べた。実際には**列挙に無い「いくつも」**を使われて失敗した。

これは Ch.1 INVEST・Ch.2 AIペルソナで既に学んだはずの罠を、除外リストという別の形で
作り直したもの。2回目で禁止列挙を削り、**書くべき1行だけを指定**したら即座に収束した。

### (4) 上限件数と候補数が食い違うと、必ず割れる

Ch.6 は「見るポイント」の表が8行あるのに、指摘の上限が7件だった。
**必ず1行落ちる設計**で、どれが落ちるかが呼び出しごとに変わっていた。
これは Ch.1 のモック確認（「2〜3件出す」）、Ch.6 の顧客指摘（「3〜4件」）で
既に潰したのと同じ形。**上限を撤廃し、該当するものは全部出す**が正解。

### (5) 条件の穴は「想定していない提出物」で露見する

Ch.6 の表6行目の条件は「予約を**消したと書いてあるが**、残骸への言及が無い」だった。
今回の薄い提出物は要件外機能に**一切触れていない**ため、厳密には該当しない。
拾う体と飛ばす体に割れたが、**厳密に読んで飛ばしたほうが正しかった**。
条件側を実態に合わせて広げた。

### (6) 評価モードとレビューモードで、仕様の厚みが非対称だった

評価モードには「必ず全部出力する」リストと観点ごとの到達点があるのに、
**レビューモードには出力仕様が1つも無かった**。何を出すか・何を出してはいけないか・
ヒントをどこまで具体的にするかが、すべてインスタンス任せだった。

## 6. Ch.1・Ch.2 の収束（★末尾の指示は落ちる）

Ch.4〜Ch.6 と同じ出力仕様を入れたが、Ch.1・Ch.2 は1回では収束しなかった。

- Ch.1：文章側の〈仮定〉を出す体と出さない体に割れ、モック反応も食い違った
- Ch.2：Excel移行の1件差は解消したが、今度は新設した10行目（自己点検の記録）で割れた
- **両章とも、追加した申告行（`飛ばした行：なし`）を一度も出力しなかった**

原因は**配置**だった。

| | 指示の置き場所 | 結果 |
|---|---|---|
| Ch.4 の残数の1行 | 出力構成の**3番目（真ん中）** | 毎回守られた |
| Ch.1・Ch.2 の申告行 | 「指摘の**最後に**書く」 | 一度も出なかった |

**指摘を書き終えた時点で応答として完成してしまうため、末尾の指示は落ちる。**
列挙を強制したいなら、**指摘より前**に置く必要がある。

そこで条件文は一字も変えず、**申告を「最後に」から「指摘を書く前に」へ移した**。

```
2. ★指摘を書く前に、下の表の10行を1行ずつ判定して並べる。この見出しで出す：

   ## 見るポイントの点検（10行）
   1 該当 ／ 2 該当 ／ 3 非該当（理由）／ …

3. 上で「該当」にした行を、表の順に全部指摘する（「該当」と書いた行を飛ばさない）
```

**結果：Ch.1・Ch.2 とも一発で収束した。**

- Ch.1：モック反応・文章側7項目とも一致。**飛ばした項目（名前の見え方・不明データ）も、
  飛ばした行（7 仮定の明示）も、2体が同じ行を同じ理由で飛ばした**
- Ch.2：指摘の集合が一致。**飛ばした行（1 Ch.1との矛盾 — 引き継ぎブロックが無く照合材料が無い）も同じ**
