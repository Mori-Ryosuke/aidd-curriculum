# logs/ — 演習セッションの記録

演習を1回通したときの記録を、日付ごとに残す場所です。

## 命名規則

```
YYYY-MM-DD_ChN_<種類>.md
```

## 4種類の記録

| 種類 | 内容 | 主な用途 |
|---|---|---|
| `逐語ログ` | 出題から採点までのやりとりを時系列で全記録 | 何がどう決まったかを後から追う |
| `提出物と採点結果` | 最終要件定義書＋採点結果＋引き継ぎブロック | 成果物のアーカイブ／次章への入力 |
| `受講者振り返り` | 効いた動き・弱かった動き・次回のチェックリスト | 受講者自身のスキル改善 |
| `カリキュラム改善メモ` | 罠の機能具合・詰まった箇所・変更提案 | 出題者としての教材改善 |

### 2026-08-21 — 質の異なる提出物での再現性（上の続き）

同じ教材が、**提出物の出来によらず同じ判定を出すか**を確かめた記録。
これまでは「中くらいの出来」1種類でしか測っていなかった。

- [薄い提出物での測定](./2026-08-21_全章_薄い提出物での再現性測定.md)
  見出しだけ埋めて中身が無い提出物。**Ch.1・Ch.3・Ch.4・Ch.6 が割れた**
  （無修正で通ったのは Ch.2 と Ch.5 だけ）
- [高品質提出物での測定](./2026-08-21_全章_高品質提出物での再現性測定.md)
  到達点をすべて満たす提出物。**割れたのは Ch.2 の1観点のみ**、他5章は一発で全観点一致

**結果：中品質・薄い・高品質の3種類すべてで、全6章が収束した。**

**この2件で得た教訓**：
- **上限（達成）の条件は揺れない。** 揺れるのは常に、その観点だけが空に近いときの**下限側**。
  中品質だけで測ると下限を一度も踏まないので、未定義でも収束済みに見える
- **判定条件に「意味を読む」作業を入れない。** 目で数えられる形にする
  （Ch.3 の DoD は「対象が特定されていれば」という意味判断のせいで、2体そろって想定と逆に着地した）
- **打ち消しで直そうとしない。** 「Xなら未達。ただしYなら未達にしない」は前半だけ読まれる。
  未達の条件は**数ではなく言葉**で定義し、残りは「それ以外はすべて一部」に倒す
- **条件文を精密にするより、判定材料の在り処を1か所に絞るほうが効く。**
  Ch.2〈AIペルソナ活用〉は条件文を3通り書き換えても収束せず、提出フォーマットに
  専用の記入欄を設けて「そこだけを見る」と決めた1回の変更で収束した
- **判断面を2つ持たせない。** Ch.2 で一度も割れなかった観点は、いずれも
  「チェックリストの項目Xの判定をそのまま使う（別途判断しない）」形だった

### 2026-08-24 — レビューモードの再現性（最後の未測定項目）

採点ではなく**指摘だけを返すモード**の測定。受講者は評価に出す前にここを何度も使うので、
揺れると**受け取るヒントの量そのものが人によって変わる**。

- [レビューモードでの測定](./2026-08-24_全章_レビューモードの再現性測定.md)

**結果：全6章が収束。これで評価モード（中品質・薄い・高品質）とあわせ、全4条件が揃った。**

**この測定で見つかった最も重い不具合**：Ch.1 で**モード違反**が出た。
「レビューして」に対し1体が**評価モードへ昇格**し、スコア表・引き継ぎブロック・
**隠し論点3つの名指し**まで出力した。受講者が一言お願いしただけで答えが流出する状態だった。
（原因：動作モードの列挙にレビューが無く、「提出仕様があれば評価」と「迷ったら評価」が
昇格側に押していた。以前入れた「降格するな」の対策が、逆向きの事故を招いていた）

**この2日で確定した、効く対策の3つの型**（条件文の精密化はほぼ効かない）：

| 型 | 例 |
|---|---|
| **書く文字列を1つ指定する** | `**5個中 M個 検出。残り N個。**` |
| **飛ばし・内訳を申告させる** | 「飛ばした行：なし」／「内訳と合計を一致させる」 |
| **見る場所を1か所に固定する** | 提出フォーマットに専用の記入欄を作り「そこだけ見る」 |

**あわせて分かった落とし穴**：
- **禁止の列挙は抜け道を作る**（「複数／まだあります」を禁止したら「いくつも」を使われた）
- **上限件数と候補数を食い違わせない**（候補8個に上限7件だと必ず1件落ちる）
- **末尾の指示は落ちる**（「最後に申告する」は一度も出力されず、前方に移したら一発で効いた）
