# 全章：薄い提出物での判定再現性 測定記録

- 実施日：2026-08-21
- 対象：Ch.1〜Ch.6 の各採点エージェント（評価モード）
- 目的：**未着手項目が並ぶ提出物**でも、受講者ごとに判定が揃うかを確かめる
- 前提：この作業では `.claude/agents/**` の deny を一時的に外して編集し、作業後に必ず復元している

---

## 1. なぜこの測定をしたか

これまでの判定ブレ削減は、**中くらいの出来の提出物**だけで測っていた。
だが実際の受講者は、初回で「見出しだけ埋めて中身が無い」提出物を出してくる。

薄い提出物では、判定条件の**下限側**（0件のとき何になるか）が問われる。
中品質では一度も踏まれない経路なので、そこが未定義でも収束済みに見えてしまう。

### 第4ラウンド（Ch.1 のみ・修正が逆方向に効いた）

INVEST を「一部」に固定する修正を入れたところ、**2体とも未達**になった（修正前は2体とも一部）。
さらに〈スコープ〉が 一部／未達 に割れた（それまで揃っていたのは偶然だった）。

原因はセルの書き方。入れた文言はこうだった：

> 0本（ストーリーの記述そのものが無い）**なら未達**。1本以上あるなら…満たす数が **0〜1なら一部**
> （★2本しかなく「なぜ」も無い場合は 0 だが、ストーリーは存在するので一部。**未達に落とさない**）

論理としては閉じているが、**同じセルの中で「0」と「未達」を一度結びつけてから、あとで打ち消している**。
2体とも前半の対応づけを拾い、打ち消しのほうを読み落とした。

### 第5ラウンド（Ch.1・書き換え後）

0 という数を未達に一度も触れさせない形に書き換えて、**全11観点一致**（INVEST＝一部、スコープ＝一部）。

- 未達の条件を**数ではなく言葉**で定義する（「ストーリーが1本も書かれていない提出物だけ」）
- 残りは「2なら達成／**それ以外はすべて一部**」とし、0 に個別の行き先を与えない
- 〈スコープ〉も同形に（未達は「4区分のどれにも1件も無い場合だけ」／Won't が空でも一部）

## 5. 分かったこと

### (1) 「あるか／ないか」で書いた条件は、0件のときに必ず割れる

これは既知だったが、今回はっきりしたのは**割れていない条件にも同じ弱点が潜んでいる**こと。
中品質の提出物では下限を踏まないので、収束済みに見えていた。

### (2) 揃っていても、狙った基準に揃っているとは限らない（Ch.3 の DoD）

2体とも「一部」で完全に一致していた。一致だけを見れば合格。
だが両方とも★の除外規定（「テストが全部通ること」は数えない）を無視していた。

原因は条件の書き方。「**対象のテストが特定されていなければ**数えない」という**意味の判断**を求めていたため、
「4層の表にテストが書いてあるから特定されている」と読める余地があった。

→ **数値か固有名が一文の中にあるか**という**見た目の判断**に置き換えて解決。
→ 教訓：**判定条件に "意味を読む" 作業を入れない。** 目で数えられる形にする。

### (3) 汎用の判定語定義と、観点ごとのカウント条件が衝突する

Ch.1 の〈INVEST〉で発生。カウント条件は「0なら未達」と書いてあったが、
2体とも**汎用の定義**（未達＝該当する記述が無い）を優先して「一部」にした。
ストーリー自体は存在するため、そちらの読みも筋が通っている。

ここは仕様側を折った。理由：2本を未達にすると、**ストーリーを1本も書いていない提出物と区別がつかなくなる**。
未達に残る意味を保つほうを取った。

なお〈非機能〉と〈AC網羅性〉は同じ形で「0なら未達」が守られている。
違いは、**その提出物の文面をそのまま使った例が条件のすぐ下に書いてあるか**。
　例：「速く動くこと。安全であること。」だけの提出物 → 3領域とも 0 → 未達

→ 教訓：カウント条件を書いたら、**想定する薄い提出物の文面を、そのまま例として添える。**

### (4) ★打ち消しで直すと、打ち消される前の対応づけのほうが残る

これが今回いちばん新しい発見。

「Xなら未達。ただしYの場合は未達にしない」と書くと、**前半の対応づけだけが読まれる**。
後半の打ち消しは効かない。論理として閉じていても関係ない。

→ 直し方：**打ち消しを足すのではなく、そもそも結びつけない。**
　　✗「0なら未達。ただし記述があれば一部に上げる」
　　○「未達にするのは**1本も無い提出物だけ**。それ以外は 2なら達成／**それ以外はすべて一部**」
　　★未達の条件は**数ではなく言葉**で定義すると、数との誤った対応づけが起きない

これは「0件のときの行き先を書き足す」という当初の対策そのものに潜んでいた罠だった。
下限を書き足すときは、**書き足し方**まで気をつける必要がある。

### (5) 内訳と合計は、書く順序を固定しないとずれる

Ch.3 と Ch.6 で同じ壊れ方をした。どちらも**合計を先に書いてから内訳を書いた**ケース。
「列挙が先、合計が後。食い違ったら列挙が正」と手順で書いて解消。
