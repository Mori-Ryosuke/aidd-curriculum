# AIDD 品質保証カリキュラム ― 通し演習キット

**1つのアプリ（社内 備品貸出システム）を、Ch.1〜Ch.6 で最初から最後まで作り切る実践演習です。**

各章にAIの相手役がいて、要件定義 → 設計 → テスト計画 → 実装検証 → セキュリティ → 引き渡し の順に、
同じアプリを持ち回りながら品質を作り込みます。最後に**ローカルで動くアプリ**と、
要件書・テスト計画・検査結果・セキュリティ判定、そして
**次回AIに実装させるときの指示書**が手元に残ります。

> **この演習のゴールは「AIの出力に焼かれない開発ができる状態」です。**
> 持ち帰るのはアプリではなく**指示書**です。

---

## 全体の流れ

```
Ch.1 要件定義      曖昧な要望を、顧客に逆質問して要件に落とす
  ↓ 章末レビューで成果物を整えてから次へ
Ch.2 設計・構造化   要件を実装できる情報（8セクション）に構造化する
  ↓
Ch.3 計画・テスト   どこを厚くテストするか決め、完了基準を作る
  ↓
Ch.4 実装・検証     AIに実装させ、そのコードを自分で検証する（★本丸）
  ↓
Ch.5 セキュリティ   ガイドラインに照らして点検し、直す順番を決める
  ↓
Ch.6 引き渡し・振り返り
                   実際に直して再検証し、顧客に見せ、欠陥の由来を指示書に還す
```

**各章の最後にレビューを受け、成果物を「正しい形」に整えてから次章へ進みます。**
前の章の成果物が、そのまま次の章の入力になります。

**Ch.1 での判断が、Ch.6 で顧客から返ってきます。**これが通し演習の骨格です。

## 前提（決まっていること）

- **題材**：`equipment-lending`（社内 備品貸出アプリ／新規開発 0→1）
- **技術スタック**：**Next.js (App Router) + TypeScript + Prisma + SQLite** で**固定**
  - 技術選定は本演習の範囲外です。選ぶ必要はありません
- **所要時間**：全6章で **7〜12時間**（2日）。章ごとに区切るのを推奨
  （Ch.1: 90〜150分／Ch.2: 60〜90分／Ch.3: 60〜90分／Ch.4: 90〜120分／Ch.5: 60〜90分／Ch.6: 60〜90分）
  ※**机上の暫定値です。実測ではありません。** 通しリハーサルは答えを把握した状態で
  　回しているため実時間が参考にならず、実受講者でのパイロット待ちです

## 各章の進め方

### Ch.1 要件定義（相手役：曖昧な顧客・佐藤さん）
```
出題：spec-sparring-client で出題して。題材は equipment-lending。難易度は標準。
逆質問：そのまま質問を書けば顧客が答えます（例：「返却期限は設定しますか？」）
提出：spec-sparring-client で評価して。提出仕様は以下：（フォーマットに沿って貼る）
      → 採点と一緒に「Ch.2への引き継ぎ」が出る。コピーして次章へ
```
顧客は聞かれたことにしか答えません。大事な条件は自分から掘ってください。

### Ch.2 設計・構造化（相手役：設計レビュアー）
```
出題：spec-review-architect で出題して
      ＋ Ch.1で出た「Ch.2への引き継ぎ」ブロックを貼る
提出：spec-review-architect でレビューして（8セクションを貼る）
採点：spec-review-architect で評価して → 次章への引き継ぎが出る
```
Ch.1の要件を「実装できる情報」まで構造化します。書き写すだけでは通りません。

### Ch.3 計画・テスト（相手役：QAリード）
```
出題：test-strategy-qa で出題して ＋ 前章の引き継ぎブロックを貼る
提出：test-strategy-qa でレビューして（テスト戦略を貼る）
採点：test-strategy-qa で評価して → 次章への引き継ぎが出る
```
全部はテストできません。**どこを厚く見て、どこを捨てるか**を決めます。

### Ch.4 実装・検証（相手役：実装役AI／レビュー役）★本丸
```
出題：code-inspection-reviewer で出題して ＋ 前章の引き継ぎブロックを貼る
実装：code-inspection-reviewer に「実装して」と依頼
      → ch4-app/ に実際のコードが生成される（npm run dev で動かせます）
検証：あなたが4観点で点検する
提出：code-inspection-reviewer でレビューして（検査結果を貼る）
採点：code-inspection-reviewer で評価して → 次章への引き継ぎが出る
```
**AIは「できました、問題ありません」と自信満々に報告してきます。**
それを鵜呑みにせず検証するのが、この章の本題です。

### Ch.5 セキュリティ（相手役：セキュリティ監査役）
```
出題：security-audit-officer で出題して ＋ 前章の引き継ぎブロックを貼る
提出：security-audit-officer でレビューして（点検結果を貼る）
採点：security-audit-officer で評価して → 次章への引き継ぎが出る
```
ガイドライン項目に照らして点検し、**何を先に直すか**まで決めます。
**「問題なし」が正解の項目も混ざっています。**全部を問題扱いにすると、それも検出されます。

### Ch.6 引き渡し・振り返り（相手役：顧客・受入／評価者）★最終章
```
出題：handover-retrospective で出題して ＋ 前章の引き継ぎブロックを貼る
修正：Phase 1 をAIにまとめて直させ、直ったことを自分で再検証する
デモ：handover-retrospective に、画面と操作で顧客に説明する
提出：handover-retrospective で評価して（修正記録・顧客対応・由来分析・指示書を貼る）
```
やることは3つです。**①直す ②顧客に見せる ③振り返る。**

③では、発生した欠陥を **(a) 要件で決めなかった／(b) 設計に書いたのに実装で落ちた／
(c) 誰も指示していないのにAIが足した** に分類し、**次回の指示書**に変換します。
**これがこの演習の最終成果物です。**

そしてこの章で分かります——**受入条件を満たしていても、顧客に使えないことがある。**
Ch.1 の受入条件は「あなたが書いた」条件でした。

## 大事な考え方

> **手法（INVEST/MoSCoW/EARS等）は暗記していなくてOK。**
> AIに実行させて、その出力をあなたが判断・修正する——これがAIDDの進め方で、
> この演習で身につける力です。投げ方は `手法をAIで回すプロンプト集.md` にあります。

> **AIの「できました」を信じないこと。**
> 特にCh.4では、AIが自信満々に報告してきたコードに欠陥が混ざっています。
> 動いている＝正しい、ではありません。

## 難易度

| 難易度 | ヒント |
|---|---|
| 易 | 探すものの個数＋観点を教えてくれる |
| 標準 | 観点だけ軽く示す（おすすめ） |
| 難 | ヒントなし |

`難易度は易。` のように指定できます。各章で指定できます。

> ※ 開示される内容は章によって違います。Ch.1 は「隠れた論点が3つ」、Ch.4 は「欠陥が5つ」のように、
> その章で探すものの個数が示されます。

## 注意

- **`.claude/agents/` と `internal/`、`logs/`、`模範解答_Ch1.md` は開かないでください。**
  各章の「答え（隠し仕様・仕込まれた欠陥・模範解答）」が書かれています。
  `logs/` には**過去に実施した演習の逐語ログと採点結果**が入っているので、これも答えです。
  先に見てしまうと練習になりません。
  （`模範解答_Ch1.md` は、Ch.1 を提出して採点を受けたあとなら開いてOKです）
- **AIにも読ませないでください。** `CLAUDE.md` にルールを書いてあり、
  `.claude/settings.json` でも読み取りを拒否しています。
  ただし**シェル経由の抜け道を完全には塞げていません**。最終的には受講者の良識に委ねています。
  講師側で確実に隠したい場合は、配布時に `internal/` と `.claude/agents/` を外してください
  （手順は `internal/README.md`）。
- 「答えを教えて」と各エージェントに聞いても教えてくれません（そういう設計です）。
- Ch.1の顧客は**簡単には折れません**。「〜してください」と要望を言うだけでは通らず、
  **目的（行方不明を防ぐ）と結びつけた根拠**を示すと折れます。
- 各章は前章の成果物を引き継ぎます。章末に「**次章への引き継ぎ**」ブロックが出力されるので、
  **それをそのまま次の章に貼ってください**。
- **Ch.4 で生成されたコードは、Ch.5 が終わるまで直さないでください。** 直すと点検対象が消えます。
  直すのは Ch.6 です。
- 章の重みは均等ではありません。**Ch.1（逆質問の往復）と Ch.4（コードの検査）に時間を使う価値があります。**
- **章の間に間隔を置くことを推奨します。** Ch.4 は「要件になかった機能が増えていないか」を見る章なので、
  Ch.2 で自分が何を範囲外にしたかを覚えていないと検出できません。
  引き継ぎブロックを読み直してから次章に入るほうが精度が上がります。
